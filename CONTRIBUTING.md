# Contributing

This app decides when a car's settings change. That single fact drives everything below.

## Ground rules

1. **MG4Tasker never writes to the vehicle.** Every write goes through MG4Control, which
   owns the privileges and the speed gate. A patch that reaches the car directly will be
   rejected regardless of how useful it is.
2. **Unreadable is not false.** A condition whose value could not be read makes the rule
   *not evaluable* — it must not fire. Never default a missing reading to 0 or false; that
   would write to a car on an assumption.
3. **Fail closed.** Unknown firmware, unreadable speed, missing bridge: refuse or omit, do
   not guess. The speed gate refusing is the system working.
4. **Say what you did not verify.** Most vehicle behaviour can only be confirmed on a car.
   "Builds and unit tests pass, not tried on the vehicle" is a good PR note. Silence
   implying road-testing is not.

## Before opening a PR

```bash
mise run check      # permission gate + lint + unit tests
```

or, without mise:

```bash
bash .github/security/check-permissions.sh
./gradlew testDebugUnitTest lintDebug
```

New behaviour needs a unit test. The decision logic — `ConditionEvaluator`, `RuleEngine`,
`FirmwareSupport` — is deliberately free of Android types so it runs on the JVM; put
testable logic there rather than in a fragment or service.

## Adding a condition or action

One enum line in `ConditionType` or `ActionType`, one string in `values/strings.xml` (and
`values-fr/`), and — for a vehicle entry — one `@SupportedOn(...)` naming the firmware
generations it works on. The editor builds itself from the `ValueSpec`. For a vehicle
action, add the matching branch to `TaskerBridgeService.dispatch()` in MG4Control.

`docs/firmware-matrix.md` is generated by `FirmwareMatrix` and refreshed by the test run —
do not edit it by hand. A test fails if a vehicle entry is missing its `@SupportedOn`.

## Permissions

Any new `uses-permission` fails CI until it is added to
`.github/security/permission-allowlist.txt` **with a justification comment**. An app on a
car should not gain capabilities quietly.

## Language and licence

English by default — code, comments, commit messages, docs. User-facing strings live in
`values/` (English) with a French `values-fr/` translation. Contributions are accepted
under MIT (see [`LICENSE.md`](LICENSE.md)).

## Commit messages

Explain **why**, not what — the diff already says what. If you fixed something subtle, say
what the failure looked like, so the next person recognises it.
